# ПОШАГОВАЯ ИНСТРУКЦИЯ: запуск «Профиль заказчика в регионе» на GitHub
### Время: ~30 минут. Ничего устанавливать на компьютер не нужно — всё через браузер.

---

## Что в пакете (архив `profil-zakazchika-github.zip`)

```
index.html                          — дашборд (это наш HTML, уже переименован)
regions.json                        — данные всех 89 регионов
update_bot.py                       — бот-обновлятор (запускает GitHub сам)
.github/workflows/update-regions.yml — расписание запусков бота
INSTRUKCIYA.md                      — этот файл
```

---

## ШАГ 1. Создать репозиторий (5 минут)

1. Зайти на **github.com** под своим аккаунтом → зелёная кнопка **New** (или github.com/new).
2. **Repository name:** `region-profile` (или любое своё).
3. Видимость: **Public**.
   > Почему Public: бесплатный GitHub Pages работает только в публичных репо.
   > В данных сейчас нет ничего закрытого (открытые источники + экспертные оценки).
   > Когда появятся закрытые данные ЦР — переезжаем в закрытый контур, это учтено.
4. Галочку «Add a README» можно не ставить → **Create repository**.

## ШАГ 2. Загрузить файлы (5 минут)

1. Распаковать архив `profil-zakazchika-github.zip` у себя на компьютере.
2. В пустом репозитории нажать ссылку **uploading an existing file**.
3. Перетащить в окно: `index.html`, `regions.json`, `update_bot.py`, `INSTRUKCIYA.md`.
4. Внизу нажать **Commit changes**.
5. Папку `.github` браузер перетаскиванием не всегда берёт, поэтому workflow создаём руками:
   - В репозитории: **Add file → Create new file**.
   - В поле имени ввести ровно: `.github/workflows/update-regions.yml`
     (слэши создадут папки автоматически).
   - Открыть файл `update-regions.yml` из архива любым блокнотом, скопировать всё
     содержимое, вставить в окно на GitHub → **Commit changes**.

## ШАГ 3. Включить GitHub Pages (3 минуты)

1. В репозитории: **Settings → Pages** (левое меню).
2. Раздел **Build and deployment** → Source: **Deploy from a branch**.
3. Branch: **main**, папка **/ (root)** → **Save**.
4. Подождать 1–2 минуты, обновить страницу — вверху появится адрес вида:
   `https://<ваш-логин>.github.io/region-profile/`
5. Открыть этот адрес. Дашборд должен загрузиться, и в правом верхнем углу
   панели будет написано **«источник: внешний источник»** — значит, страница
   сама нашла regions.json. ✅ Контрольная точка 1 пройдена.

## ШАГ 4. Вписать постоянный адрес данных в файл (5 минут)

Это нужно, чтобы кнопка «⬇ Обновить из интернета» работала в один клик у ЛЮБОГО,
кто скачал файл, — в том числе при открытии с рабочего стола.

1. В репозитории открыть `index.html` → нажать иконку **карандаша** (Edit).
2. **Ctrl+F** в окне редактора → найти строку:
   ```
   "" /* сюда вписать https://raw.githubusercontent.com/<user>/<repo>/main/regions.json */
   ```
3. Заменить её на (подставив свой логин и имя репозитория):
   ```
   "https://raw.githubusercontent.com/<ваш-логин>/region-profile/main/regions.json"
   ```
   Кавычки оставить, комментарий можно стереть. Запятая перед этой строкой уже стоит.
4. **Commit changes**.
5. Проверка: скачать `index.html` себе на компьютер (кнопка Download raw file),
   открыть двойным кликом → нажать **«⬇ Обновить из интернета»** → должно
   появиться окно «Данные обновлены. Загружено регионов: 89». ✅ Контрольная точка 2.

## ШАГ 5. Подключить бота-обновлятора (7 минут)

1. Получить API-ключ: **console.anthropic.com** → Settings → API Keys →
   **Create Key** → скопировать (показывается один раз). Пополнить баланс
   на $5–10 — бюджета хватит на месяцы работы бота.
2. В репозитории: **Settings → Secrets and variables → Actions →
   New repository secret**:
   - Name: `ANTHROPIC_API_KEY`
   - Secret: вставить ключ → **Add secret**.
3. Пробный запуск: вкладка **Actions** → слева workflow **update-regions** →
   кнопка **Run workflow** → mode: `ratings`, filter: `full` → **Run workflow**.
4. Через 2–4 минуты запуск станет зелёным. Зайти в **Commits** — должен появиться
   коммит `auto-update regions.json` от regions-bot. ✅ Контрольная точка 3.
5. Открыть страницу дашборда → «⬇ Обновить из интернета» → свежие данные
   подтянулись. Цепочка замкнулась.

Дальше бот работает сам по расписанию:
- **1-е число каждого месяца** — свежие рейтинги (АПЭК, Минченко) и высказывания
  по исследованным регионам;
- **2 января / 2 апреля / 2 июля / 2 октября** — проверка смены глав по всем 89
  (сезоны «губернаторопадов»).

## ШАГ 6. Раздача файла коллегам

Два равнозначных способа:
- **Ссылка** на `https://<логин>.github.io/region-profile/` — всегда свежая версия.
- **Файл**: скачать `index.html`, переслать кому угодно. У получателя работает
  всё, включая кнопку «⬇ Обновить из интернета» (адрес данных уже вшит шагом 4).

---

## Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| Страница Pages показывает 404 | Подождать 2–3 мин после включения Pages; проверить, что файл называется ровно `index.html` |
| «источник: встроенные данные» на Pages | `regions.json` не в корне репо или опечатка в имени |
| Кнопка «Обновить из интернета» просит URL | Шаг 4 не сделан или логин/репо в URL с опечаткой; вставить URL в окно — заработает на сессию |
| Actions-запуск красный, ошибка «ANTHROPIC_API_KEY» | Секрет не создан или имя не точное (шаг 5.2) |
| Actions красный, ошибка API 4xx | Нет средств на балансе console.anthropic.com |
| Бот отработал, но данных нет | Посмотреть лог запуска в Actions — там по каждому региону ✓/✗ с причиной |
